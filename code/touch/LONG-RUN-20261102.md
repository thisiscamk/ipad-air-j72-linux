# 2 November: continuous-touch lifetime limit

The #35 worker stopped after **120,300 input frames and seven recoveries**.
There were no layout rejects, transfer errors or reported input timeouts.
The existing code fails on the seventh recovery over the entire session, even
when earlier recoveries are separated by minutes. Its budget is cumulative,
so a long session can stop after isolated transient bursts.

The failure happened 42 seconds into a separate 60-second CPU-governor
comparison. Earlier recoveries predate that comparison; causality is unproved.
The governor was restored. The final anomaly ring retains only 32 of 30,547
wire anomalies; 30,515 old records were overwritten. This is not a full trace.

The worker reports final firmware health and successful restoration of the
reset/CS pins, analog rails, PWM and power domains (`cleanup_failed=0`). Its
public `cleanup_ok` flag also requires acquisition success, so the overall
session/cleanup API failed. The normal stop wrapper correctly refused that
check. The remaining radio stop was then completed separately; no failed-worker
restart or relaxed guard was attempted. The device returned to iOS for charging.

Next: test a bounded recovery-rate policy with explicit stop reasons, preserve
short-burst protection, and investigate retained wire anomalies. Do not simply
remove the limit or describe reported physical restoration as a successful input
session. Candidate changes still need hardware qualification.
